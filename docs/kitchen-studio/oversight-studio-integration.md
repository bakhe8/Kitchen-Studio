# دفتر الإشراف: إدارة المشروع عبر دورة العمل

تاريخ التنفيذ: 4 نوفمبر 2026. المسار الفعلي: `index.html?panel=workshop&step=oversight`.

## نموذج الكائنات والمهام

ينطلق المشرف من مشروع ونسخة محددة، ثم يختار مرحلة وعائقًا أو اعتمادًا، وينتقل إلى الكائن الذي يحتاج إجراء. تحتفظ العودة بالمشروع والإيصال والمرحلة والبند المحدد. لا تدمج اللوحة مشاريع مختلفة في نسبة إنجاز عامة.

| الكائن | الهوية والعلاقة | الفعل المتاح |
| --- | --- | --- |
| مشروع | نسخة عمل محلية أو مشروع فريق يملكه الحساب الحالي | اختيار، تحديث، فتح نسخة الفريق للعمل من شاشة المشاريع |
| نسخة | رقم الإصدار وهوية الحساب والصلاحية | معاينة مستقلة؛ فتح صريح قبل تحرير التصميم |
| مرحلة | واحدة من سبع مراحل مرتبطة بالمشروع | تحديد وعرض الحالة وأعمالها |
| عائق | سؤال الدليل الأصلي أو بند مشتق من سجل التنفيذ | معاينة جواب سريع أو فتح البند في سياقه |
| اعتماد | الهيكل، العميل، مراجعة نسخة المشروع، الكتالوج، الوصفات، شروط التسعير | عرض صلاحية الاعتماد وفتح شاشة الاعتماد الأصلية |
| إيصال | إيصال تصنيع مختار صراحة، مرتبط بمشروع وإصدار | عرض تنفيذ وحداته، مع إظهار اختلاف إصدار الإيصال عن النسخة الحالية |
| وحدة | هوية الوحدة داخل الإيصال | فتح فحص الجودة أو التركيب أو الاستلام |
| بلاغ | مرتبط بوحدة ومحضر استلام، وله تسلسل أحداث خدمة | فتح البلاغ نفسه وتشخيصه ومعالجته ومراجعته |

المهام الأساسية: معرفة ما يحتاج إجراء ولماذا، تحديد المسؤول، الوصول إلى الموضع الصحيح، معاينة أثر القرار، حفظه أو التراجع عنه، ثم العودة للتحقق من النتيجة. النموذج الذهني المقصود هو «أين توقف هذا المشروع وما الخطوة التالية؟».

## مصدر الحالة وقواعدها

`buildOversightReport` إسقاط مشتق لا يكتب بيانات أو يوقع اعتمادًا. يعيد استخدام دليل العمل والتحقق من الاعتمادات والكتالوج ودفتر الموقع ومحاضر التسليم والخدمة.

| المرحلة | الدليل المعروض |
| --- | --- |
| دفتر الموقع | جدران النطاق وقياساتها الموثقة المطابقة للرسم؛ لا يستنتج الرفع من الأبعاد الافتراضية |
| توزيع الوحدات | وجود التوزيع وصلاحية اعتماد الهيكل وأعمال التصميم المفتوحة |
| التشطيبات | الاختيارات المتبقية واعتماد الهيكل والعميل |
| الحصر والتسعير | العرض الحالي واكتماله وصلاحية موافقة العميل؛ السعر المجهول لا يعامل كصفر |
| التصنيع | مراجعة نسخة التصميم منفصلة عن إصدار الإيصال ونتائج جودة وحداته |
| التركيب والتسليم | الوحدات المركبة والمستلمة والملاحظات المانعة في الإيصال المختار |
| الصيانة | البلاغات المفتوحة والمغلقة بمحضر العميل؛ غياب البلاغات لا يثبت اكتمال الخدمة للأبد |

حالات العرض: `ready` «مثبت لهذه النسخة»، `attention` «يحتاج إجراء»، `waiting` «بانتظار المتطلبات»، `unknown` «غير متحقق». اللون مصحوب بنص. فشل تحميل المصدر يمسح التفاصيل القديمة؛ قائمة إيصالات محملة وفارغة تعني عدم وجود إيصال، بينما فشل القراءة يعني عدم التحقق. إغلاق بلاغ لا يحول بقية وحدات المشروع إلى مستلمة.

## آلات الحالة ودورة التفاعل

### اختيار المشروع أو الإيصال وتحديثه

`idle → loading → ready | unavailable`.

- المحفز: دخول المسار، التحديث، أو تغيير الاختيار.
- الإدخال: اختيار مشروع أو إيصال من قائمة معلومة المصدر.
- القواعد: التحقق من ملكية المشروع والحساب، رأس استجابة النسخة وإصدارها، صلاحية الأرشيف، ونطاق سجل التنفيذ؛ إعادة التحقق من الصلاحية بعد التحميل. رقم جيل الطلب وهوية المستند يمنعان اعتماد استجابة متأخرة بعد تغيير المصدر أو مغادرة الشاشة.
- التغذية الراجعة: تعطيل الإجراءات أثناء التحميل، ثم اسم المشروع والإصدار ومصدر الحالة أو رسالة عدم التحقق.
- النمط: نسخة العمل قابلة للتحرير، ومعاينة الفريق للقراءة. المعاينة لا تثبت أرشيفًا ولا تستعيد صورًا ولا تغير التخزين أو تاريخ المشروع أو ارتباط الوصول.
- الاسترداد: تحديث أو اختيار مشروع متاح أو الرجوع الصريح إلى نسخة العمل المحلية. لا تتحول هوية مشروع غير متاح إلى مشروع آخر تلقائيًا.

### تحديد مرحلة أو عائق

`selected(stage, task) → selected(nextStage, nextTask)`، أو `preview → leaveGuard` إذا كان القرار غير محفوظ.

- المحفز والإدخال: النقر أو التفعيل بلوحة المفاتيح على المرحلة أو البند.
- القواعد: البند تابع للمرحلة المختارة؛ تفاصيل المصدر والوحدة والبلاغ تظهر في أداة السياق.
- التغذية الراجعة: حالة ضغط واضحة، حدود تحديد، تحديث عنوان المرحلة ووصف العائق، وإعادة التركيز إلى المحدد.
- الحلقة: اختيار بند، مراجعة السبب والمسؤول، ثم الانتقال للإجراء أو اختيار بند آخر.
- الحالة المستقرة: السياق معروف من دون تغيير بيانات المشروع.

### الجواب السياقي والمعاينة والحفظ

`ready → calculating → preview → saving → ready`.

مسارات إضافية: `preview → cancel → ready`، و`preview → leaveGuard → stay | discardAndLeave | saveAndLeave`، و`saving → recoverableFailure → preview`.

- المحفز: جواب سريع موجود أصلًا في `guideQuickAnswers`.
- الإدخال: اختيار الجواب ثم تأكيد «حفظ القرار في المشروع».
- القواعد: `answerGuideQuestion` يحتفظ بمفاتيح السؤال الأصلي وقيوده. المعاينة تحسب تقريرًا مرشحًا دون كتابة. الحفظ يعيد التحقق من صلاحية التحرير وهوية المصدر وتغير التخزين في تبويب آخر، ثم يعيد تطبيق قواعد الجواب قبل الالتزام الفعلي.
- التغذية الراجعة: عدد الأعمال قبل القرار وبعده، وتأثيره في صلاحية الاعتمادات، ورسالة نجاح أو سبب تعذر الحفظ.
- الاسترداد: فشل الحفظ يحتفظ بالقرار للمراجعة والمحاولة؛ إلغاء المعاينة لا يغير المستند. الانتقال أثناء المعاينة يعرض حفظ ثم متابعة، ترك المعاينة، أو البقاء.
- الحفظ من دون قرار معلق يستدعي حفظ المشروع الحقيقي؛ لا يعتمد على تمرير المستند نفسه كتغيير صوري.

### التراجع والإعادة

`committed(n) → undo → committed(n−1) → redo → committed(n)`.

المحفز زرا التاريخ أو آلية الغلاف الحالية. يمر التنفيذ عبر تاريخ المشروع المعتمد، ثم يعاد اشتقاق اللوحة واستعادة التركيز والسياق. لا يتاح أثناء قرار غير محفوظ أو في معاينة فريق. محاضر الخادم وأحداث الورشة والعميل والخدمة لا تمحى بالتراجع المحلي.

### فتح الإجراء والاعتماد والعودة

`ready → checkingAccess → owningEditor → back → refreshing → ready`.

الإجراء المحلي يفتح المحرر الأصلي. في معاينة الفريق تفتح إجراءات التصميم شاشة المشاريع مع المشروع المقصود مختارًا؛ فتح النسخة للعمل يظل صريحًا. تتلقى شاشتا التتبع والصيانة هوية المشروع والإيصال والوحدة والبلاغ مباشرة لأنهما تقرآن سجل التنفيذ. محرر التصنيع يقرأ مستند العمل، لذلك لا يعامل تمرير هوية وحدة إليه كفتح مشروع بعيد. تغير صلاحية الحساب أو إصدار المشروع أو المستند أثناء التحقق يوقف الانتقال ويطلب تحديث المصدر.

كل اعتماد يمر عبر شاشته وقواعده الموجودة. لا توقيع من بطاقة حالة، ولا تجاوز لاسم المعتمد أو تحقق الإصدار أو متطلبات الإفراج أو محضر العميل. سجل الموافقات المعروض مستقل عن صلاحية توقيع محفوظ داخل الأرشيف؛ تعذر قراءة السجل يظهر صراحة.

## اللغة البصرية والاستجابة

شريط سباعي للمراحل، ومساحة أعمال، وأداة سياقية ملازمة للبند. ألوان هادئة مع نص الحالة، ومصدر واضح قبل الإجراءات. تخطيط سطح المكتب يضع السياق بجوار الأعمال في اتجاه RTL، واللوحي يحتفظ بشريط مراحل قابل للتمرير داخل حدوده، والهاتف يكدس مساحة العمل وأداة السياق. أزرار بحد أدنى 44 بكسل، وتركيز مرئي، واحترام تقليل الحركة. الانتقالات قصيرة وتوضح التحديد؛ لا تحرك الكائنات أو تعيد ترتيبها بما يفقد موضع المراجعة.
