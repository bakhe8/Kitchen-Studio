أول تشغيل كامل أعطى237/240 وكشف ثلاث حالات، ثم أُعيد التشغيل كاملًا بعد المعالجة:

- **فهرس المصادر:** أعيد توليد `docs/design-system/inventory.json` بالمولّد الموجود ليشمل وحدة التفاعل الجديدة وبصمات الملفات الحالية. كان فحص حداثة الفهرس يفشل في النسخة الأساسية أيضًا؛ أما اكتمال قائمة JavaScript فتطلب إضافة الوحدة الجديدة.
- **توقيت اختبار الإشراف:** كان `settle()` ينتظر هدوء طلبات الشبكة، بينما يواصل `buildOversightReport` حساب الموافقات غير المتزامن بعدها. نجح الاختبار منفردًا على النسخة الأساسية والفرع، وفشل تحت الحمل المتوازي عند قراءة الحالة قبل اكتمالها. أُضيف إلى `choose()` انتظار محدود لاكتمال تحديث الواجهة، ممثلًا بإعادة تمكين زر refresh، قبل إجراء assertions نفسها. لم يتغير كود المنتج أو توقع `ready/unknown`.

## نوع الإثبات وحدوده

اختبارات المتحكم تشغل وحدات المنتج الحقيقية على DOM مصغر، وأحداث مؤشر/لوحة مفاتيح مصطنعة، وتخزين اختباري. اختبار العودة يشغل `mountWorkshop` ومساري `openUnitContext.save/cancel` و`kitchenProjectURL` الفعلية، ثم يختبر إعادة تركيب المصمم بالسياق. **لم يُشغّل إقلاع `kitchen-editor.js` الكامل في متصفح ضمن هذا التحقق.**

أُعدت صفحة معاينة مؤقتة تستعمل CSS ووحدات المصمم وCAD الفعلية وfixture الأربع وحدات. لم تصل بيئتا المتصفح المتاحتان إلى عنوان المعاينة المحلي؛ أعادتا `ERR_CONNECTION_REFUSED`. لذلك لا توجد نتيجة ناجحة مزعومة للمتصفح، ولا لقطة شاشة تُقدّم كدليل بصري.

نجحت الفحوص الشاملة والبناء كما سبق، لكن لم يكتمل اختبار إقلاع التطبيق والتنقل الفعلي في المتصفح. بقيت المراجعة البصرية واختبارات الأجهزة الحقيقية خارج الإثبات الحالي.
