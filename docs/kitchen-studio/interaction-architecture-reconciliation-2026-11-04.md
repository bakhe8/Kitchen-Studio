# مصالحة معمارية التفاعل مع المصدر الجاري

التاريخ: ٤ نوفمبر ٢٠٢٦. المرجع: `Kitchen-Studio-Interaction-Architecture.html`. هذه الوثيقة تطابق المواصفة المفاهيمية مع المصدر الجاري في المستودع؛ لا تنقل ادعاءات لقطة المصدر 68 إلى التنفيذ الحالي، ولا تعد اختبار استخدام بشري.

## الخلاصة

البنية الحالية ليست نقطة بداية فارغة. مسارات الرفع والمصمم والصف المصنع والحفظ تتضمن بالفعل هوية مستقرة للكائن، ومعاينة قبل التطبيق، وإلغاء السحب، وتراجعاً، وحراسة النسخة، وفصلاً بين المسودة والحفظ. المصالحة المطلوبة هي توحيد الدلالات والعقد الوسيط، ثم سد فجوات العرض والسلوك، لا إعادة كتابة محركات الهندسة.

بعد مهام المصالحة 1–4، يعالج المصدر الجاري تعارض قفل العرض الشخصي: الطلب الصريح يعدل عرض الهدف ويبقي `locks.width=true` حتى لو كان الهدف غير مقفل قبله، دون تحرير حماية الجهاز أو الموديل أو حقائق الموقع أو الأقفال الأخرى. أضيف محول نية العرض إلى مساري المصمم، وثبتت شريحة 2400/800/400 واستعادة سياق الكائن بين التفاصيل والداخل والعروض باختبارات المصدر.

«متحقق مصدرياً» أدناه يعني وجود التنفيذ واختبار آلي محدد، ولا يعني قبولاً بصرياً أو ميدانياً. «جزئي» يعني أن الدليل يغطي جزءاً من المجال. سجل المتصفح أدناه قبول جزئي للتنقل والقشرة في مشروع بلا وحدات، ومنسوب إلى الوكيل الأب الذي نفذه؛ لا يستبدل قبول تفاعل الوحدات أو جهاز لمس أو فنيين.

## القرار المعماري

لا تُنقل قواعد الهندسة إلى الواجهة. الدوال القائمة مصادر الحقيقة، وتنفذ `public/kitchen-interaction-intent.js` طبقة التنسيق المحدودة بتعديل العرض:

```text
InteractionIntent {
  sessionId, baseRevision, objectId,
  property: 'widthMm', requestedValue: integer millimetres,
  referenceEdge: 'start' | 'end' | null,
  inputKind: 'number' | 'grip' | 'button',
  explicitUserChange, withEffects
}

PreviewResult {
  status, candidate, sessionId, intentId, baseRevision,
  affectedObjects, protectedObjects,
  changedProperties, protectedProperties,
  constraintReasons, unresolvedEvidence,
  catalogRevision, measurementRevision,
  effectsStatus
}
```

`createInteractionSession(baseRevision)` ينشئ جلسة قابلة للإلغاء، و`previewInteractionIntent(doc, intent, session)` يعيد المعاينة، و`commitInteractionPreview(preview, session)` يجيز أحدث مرشح كامل الأثر فقط. الحالة `committed` تعني إجازة المرشح، لا كتابة المشروع. `intentId` يولده المحول؛ `scope` ليس حقلاً مستهلكاً في هذا التنفيذ. `measurementRevision` بصمة مؤقتة لسجل القراءات وسلاسل الجدران، لا توثيق رفع جديد. المعاينة السريعة ذات `effectsStatus='deferred'` لا تجاز للتطبيق. العقد ليس مخطط تخزين جديداً؛ التطبيق والسجل والحفظ والاعتماد عند أصحابها الحاليين.

## ترتيب التنفيذ المصالح

1. **منجز مصدرياً:** توحيد دلالة تعديل العرض والتثبيت، مع اختبار الوحدة المقفلة شخصياً واستمرار حماية المانحين والأجهزة.
2. **منجز مصدرياً:** عقد النية المشترك وتكافؤ السحب والرقم والأزرار للطلب نفسه.
3. **منجز مصدرياً:** شريحة 2400/800/400 كاملة، ضمن كتالوج العينة المحدد في وثيقة الدمج.
4. **منجز مصدرياً:** الهوية والسياق والتركيز عبر التفاصيل والداخل والعروض، ومنها النقل عبر المسار الخارجي الحقيقي.
5. **باقٍ:** مكون الخاصية الموحد وحالة الحفظ الشبكي المرتبطة بلقطة ورحلة 2350 مم وجرد بدائل السحب.
6. **باقٍ:** تعميم العقد على الخامات والأجهزة، واستكمال قبول تفاعل الوحدات في المتصفح ثم جهاز لمس وفنيين بأدلة منفصلة.

## حدود الإثبات

نجاح اختبارات المصدر لا يثبت اكتشاف الإيماءة أو سرعة الفني. نجاح رحلة الواجهة لا يثبت صلاحية وصفة المصنع. يبقى اختبار الاستخدام، واللمس الحقيقي، والتعميم على كل المسارات بوابات مستقلة.
