# عقد تعديل عرض الوحدة

تاريخ التنفيذ: 2026-11-04. النطاق: عرض وحدة من صف مصنع محفوظ، في المصمم الشامل وواجهة CAD. هذا عقد تنسيق مؤقت فوق محرك الهندسة الحالي، وليس مخططًا جديدًا لتخزين المشروع أو اعتماد تصنيعه.

## الكائنات والسياسة

هوية الهدف هي `unit.id`. يرتبط بالصف عبر `runId`، ويقابله العضو نفسه داخل `room.workshop.rows[runId].units`. يظل الصف والوحدة وكتالوج المصنع مصادر الحقائق؛ لا ينشئ العقد نسخة أخرى لقواعد التعبئة أو التسعير.

- يغيّر التعديل الصريح الفعلي عرض الهدف ويثبت `locks.width=true` في **المرشح**. يجوز للمستخدم تعديل عرضه المثبت مرة أخرى.
- تبقى قيود `position/usage/finish` وبقية بيانات الوحدة كما كانت. تغيير الجار التابع لا يثبت عرضه.
- تمنع الأقفال التبرع الآلي بالعرض. تبقى حماية الجهاز والمجلى والموديل والموضع والفراغ المقصود لدى `previewKitchenWidthChange`.
- إعادة إدخال العرض نفسه لا تنشئ تثبيتًا ولا معاملة تراجع؛ يعاد مصدر الوثيقة بهويته نفسها.
- تحفظ المعاملة المقبولة CAD ووصف صف المصنع معًا. القياسات المطلوبة بالملليمتر؛ التحويل إلى سنتيمترات CAD داخل المحرك.

## الواجهة البرمجية

```js
const session = createInteractionSession(baseDoc);
const preview = previewInteractionIntent(baseDoc, {
  objectId: unitId,
  property: 'width',
  requestedValue: 800,          // عرض مطلق بالملليمتر
  referenceEdge: 'end',        // null أو start أو end
  inputKind: 'grip',           // number / button / scrub / grip / system
  explicitUserChange: true,
}, session, {withEffects: false});

// عند الإفلات/التطبيق: الحساب الكامل على الأساس والجلسة نفسيهما.
const ready = previewInteractionIntent(baseDoc, preview.intent, session);
const accepted = commitInteractionPreview(ready, session, currentDoc);
// صاحب واجهة المهمة يضيف accepted.doc إلى المسودة أو يمرره إلى commitProject.
// cancelInteractionSession(session) يلغي الجلسة دون كتابة المشروع.
```

`session` مقبض مجمّد؛ بياناته الداخلية في `WeakMap`. يولد العقد `sessionId/intentId/baseRevision`، ولا يقبل `intentId` يفرضه المستدعي. إن أرسل المستدعي `sessionId` أو `baseRevision` وجب تطابقهما مع المقبض.

`baseRevision` رمز محلي لهوية الوثيقة غير القابلة للتعديل في مكانها. كل تعديل للهندسة **أو الأقفال أو الكتالوج أو القياس** يجب أن ينتج وثيقة جديدة. يحمي العقد من تبدل مرجع المشروع حتى مع مشاركة كائن `kitchen`. هذا لا يستبدل حراس التخزين أو الصلاحيات أو تغير المشروع في نافذة أخرى، ولا يكتشف تعديلًا مخالفًا لهذا العقد يحدث داخل المرجع نفسه.

`currentDoc` إلزامي عند الاعتماد. لا يكتب `commitInteractionPreview` في التخزين؛ يغلق جلسة التفاعل ويعيد المرشح للمستدعي. يتولى `commitProject` لاحقًا التحقق والحفظ والتاريخ. إذا رفض الحفظ في CAD، تنشأ معاينة كاملة جديدة لإعادة المحاولة، بشرط بقاء وثيقة الأساس الحالية نفسها.

## النتيجة

تحتفظ النتيجة بالحقول الأصلية `ok/doc/reason/unitId/changes/cutChanges/price/hold/notes/donors/protectedUnits` عندما يوفرها المحرك، وتضيف:

| الحقل | الدلالة الدقيقة |
|---|---|
| `status` | `valid` أو `invalid` أو `unchanged`؛ وحالات الحراسة `stale/cancelled/superseded/deferred/committed` بحسب العملية |
| `changed` | هل يوجد تعديل فعلي؟ لا يجوز إنشاء خطوة تاريخ عند `false` |
| `candidate` | الوثيقة المرشحة، أو `null` عند الرفض |
| `affectedObjects` | معرفات الوحدات التي تغير عرضها أو بدايتها أو قيدها |
| `changedProperties` | `{objectId, property, before, after}`؛ العرض والبداية بالملليمتر، والأقفال قيم منطقية |
| `protectedProperties` | قراءة لقيود المصدر؛ ليست محرك صلاحيات جديدًا. قفل الهدف الشخصي يسمح بتعديله الصريح، مع حمايته من التوزيع الآلي |
| `constraintReasons` | أسباب الرفض `{code,message}`؛ لا تُستنتج قيود هندسية جديدة بتحليل نص عربي |
| `unresolvedEvidence` | معلومات الصافي/السعر المعلقة من النتيجة الكاملة؛ `null` عند تأجيل حساب الأثر |
| `catalogRevision/catalogLayoutRevision` | المراجعتان الفعليتان من كتالوج المصدر |
| `measurementRevision` | `null`: لا يوفر نموذج المصدر مراجعة قياس كلية مستقلة؛ حراسة الوثيقة تظل فعالة |
| `effectsStatus` | `deferred` للمعاينة الخفيفة، `calculated` بعد حساب الأثر، `unchanged` لعدم التغيير، `unavailable` للرفض |

`calculated` يعني إجراء الحساب. قد يبقى السعر `null`، وقد توجد بنود مراجعة أو حارس ميزانية. لا تعني نتيجة هندسية صالحة الموافقة على التصنيع أو اكتمال الإثبات. بيانات الحماية الكاملة من المحرك لا تُستكمل في المعاينة الخفيفة.

## آلة الحالة ودورة التفاعل

حالة الجلسة الداخلية واحدة من `active/committed/cancelled`. أثناء `active` تتغير نتيجة الطلب الأخير بين عدم وجود مرشح، ومعاينة خفيفة، ومعاينة كاملة، وعدم تغيير. لا توجد عمليات حساب غير متزامنة مستحدثة؛ يمنع ترتيب النيات اعتماد نتيجة سابقة من callback أو واجهة تحتفظ بها.

| الحالة الأولية والمحفز | فعل المستخدم | القواعد والحراس | التغذية الراجعة | الحلقة أو الحالة النهائية |
|---|---|---|---|---|
| وحدة محددة؛ بدء تحرير رقم أو سحب | كتابة عرض، سحب الحافة، أو ضغط ± | إنشاء جلسة على الوثيقة الحالية؛ هوية وحدة موجودة؛ قيمة صحيحة وحافة معروفة | الحقل والقياس والمقبض يصفون الوحدة نفسها | جلسة نشطة |
| جلسة نشطة | تغيير القيمة أثناء الإدخال/السحب | كل طلب أحدث يبطل المرشح الأقدم، حتى لو كان الجديد مرفوضًا أو مساويًا للأصل؛ يفوض المحرك القيود | رسم مرشح صالح أو سبب الرفض مع إبقاء الرسم المستقر | تكرار المعاينة على الأساس نفسه |
| معاينة خفيفة صالحة | إفلات أو تطبيق الرقم | إعادة حساب الأثر الكامل؛ لا تعتمد نتيجة `deferred` | عرض أثر الجار والقطع والسعر أو سبب الرفض | مرشح كامل قابل للمراجعة |
| مرشح كامل | اعتماد التفاعل | آخر نتيجة فعلية من الجلسة نفسها، المصدر الحالي نفسه، والجلسة نشطة | تثبيت في مسودة المصمم؛ أو معاينة تأكيد الحفظ في CAD | `committed`؛ الحفظ منفصل |
| أي جلسة نشطة | Escape أو إلغاء أو فقد الالتقاط/الصلاحية | إبطال الجلسة والمرشح؛ تجاهل الإفلات المتأخر | استعادة الرسم المستقر، ثم إغلاق طبقة التفاصيل بضغط مستقل | `cancelled` |
| جلسة نشطة | يتغير المشروع خارج الجلسة | رفض الاعتماد على مصدر مختلف، ولو لم تتغير هندسة `kitchen` | رسالة تطلب معاينة جديدة | لا كتابة؛ يبدأ التحرير التالي بجلسة جديدة |
| القيمة مساوية للأصل | تطبيق/إفلات بلا تغيير | `changed=false`؛ لا قفل ولا تاريخ ولا محو Redo | المقاس السابق | `unchanged` |
| تعديل محفوظ | تراجع/إعادة | واجهة المشروع الأصلية، لقطة واحدة تشمل الهندسة والأقفال | عودة الهدف والمانحين وقيودهم معًا | مشروع مستقر محفوظ |

تبقى جهة الحافة قرارًا هندسيًا، ولا تُعكس بسبب RTL. يتطابق السحب والرقم والزر عندما يطلبون القيمة والحافة والسياسة نفسها. الإدخال الرقمي بلا حافة يسمح للمحرك باستخدام الجانبين وفق القواعد القائمة؛ سحب النهاية يقصر الأثر على جهة النهاية.

## شريحة القبول 2400 مم

| المرحلة | A | الهدف | C | D | القيود |
|---|---:|---:|---:|---:|---|
| الأساس | 600 | 600 | 600 | 600 | A وD مثبتتان؛ الهدف وC مرنان |
| طلب الهدف 800 | 600 | 800 | 400 | 600 | الهدف يكتسب تثبيت العرض؛ C تبقى مرنة |
| تثبيت C ثم طلب الهدف 900 | 600 | 800 | 400 | 600 | طلب مرفوض بعجز 100 مم؛ تبقى الحالة السابقة |
| Undo للتعديل المحفوظ | 600 | 600 | 600 | 600 | يعود قفل الهدف إلى `false` |
| Redo | 600 | 800 | 400 | 600 | يعود قفل الهدف إلى `true` |

تثبيت C شرط مقصود في حالة التعارض؛ الحد الأدنى الحالي لعائلة التخزين 200 مم، ولذلك يكون 900/300 ممكنًا عندما تبقى C مرنة. لا يغيّر المثال قواعد المصنع لإجبار التعارض.

## الإثبات

- `tools/check-kitchen-interaction-intent.mjs`: تكافؤ النية، التثبيت الصريح والآلي، الإلغاء، الاستبدال، اختلاف المصدر، وعدم اعتماد المعاينة الخفيفة.
- `tools/check-kitchen-interaction-slice.mjs`: الشريحة أعلاه عبر `commitProject/undoProject/redoProject` والتخزين الفعلي البديل في الاختبار.
- `tools/check-kitchen-designer-studio.mjs`: أحداث الرقم والسحب والإلغاء في متحكم المصمم الحقيقي، مع DOM مصغر.
- `tools/check-kitchen-designer-recovery.mjs`: تعديلان متتاليان واستعادة التثبيت، ومصدر مثبت مسبقًا.
- `tools/check-kitchen-view.mjs`: الرقم والسحب في CAD، معاينة هدف مثبت قبل الإفلات، إلغاء طبقة واحدة، حفظ فاشل قابل لإعادة المحاولة، وتراجع كامل.

هذه اختبارات للسلوك البرمجي. قياس قابلية اكتشاف الإيماءات، وزمن إنجاز الفني، والتعب أو الحمل الإدراكي، واختبار أجهزة اللمس الفعلية، يحتاج جلسات استخدام مستقلة.
